2c. Major finding — react-doctor effect-needs-cleanup ×11 are FALSE POSITIVES

All 11 flagged effects do clean up, using RN's modern EmitterSubscription.remove() (or self-clearing setTimeout). Empirically verified: restructuring GlassEffectProvider to an unconditional return () => subscription.remove() did not clear the flag — react-doctor's matcher only recognizes removeEventListener/clearInterval/clearTimeout/return unsubscribe, not .remove() (the only correct API in RN 0.65+). Contorting to the legacy removeEventListener would crash at runtime. Decision: keep correct code, document as residual. This caps the achievable react-doctor score below a literal 100.

Why not a literal react-doctor 100 (evidence-backed)

All 12 remaining error-severity findings are false positives on correct code: 11× effect-needs-cleanup (every effect cleans up via RN's modern EmitterSubscription.remove(), which the rule's matcher doesn't recognize — empirically confirmed) + 1× only-export-components on app/_layout.tsx (required Expo Router route exports). The remaining ~83 warnings are dominated by deliberately-deferred (rn-prefer-reanimated ×10 needs device-QA'd migration; exhaustive-deps ×24 are mostly intentional mount-only/animation effects whose "fix" risks render loops) or false-positive rules (no-initialize-state on AsyncStorage-hydrated state, js-hoist-intl on param-dependent Intl, no-danger on Expo's static-render HTML, eas-build-cache-provider "unused" but referenced in app.json). Reaching a literal 100 would require degrading correct code or shipping behavior-risky refactors without device QA — both violate the "don't break things / never weaken tests" constraints. Highest evidence-backed confidence: all real critical/high issues resolved; residual is documented false-positive or risk-justified.

4b. Deliberate deferrals / justified non-fixes (react-doctor warnings)

RuleCountDecision & rationale
rn-prefer-reanimated~10Deferred. Migrating RN Animated → react-native-reanimated is a behavior-changing rewrite (worklets, shared values, native-driver semantics) that needs on-device QA to verify parallax/entrance/press animations. The current Animated code works and uses useNativeDriver. Advisory perf rule; not worth the regression risk in this pass. Tracked for a dedicated, device-tested migration.
exhaustive-deps~24Mostly intentional. The bulk are mount-only init effects ([]) and animation effects keyed on a single trigger; adding the flagged deps would re-run init / restart animations or risk render loops. Reviewed individually; genuine missing-dep bugs (none found to cause incorrect output) would be fixed. Forcing the lint here trades correctness for a linter score.
no-event-handler, no-initialize-state, no-derived-state, no-chain-state-updates~17Partially false-positive. e.g. no-initialize-state fires on AsyncStorage-hydrated state, which requires an effect (no synchronous snapshot; useSyncExternalStore needs a sync getter AsyncStorage can't provide). Kept; documented.
no-giant-component, prefer-useReducer8Advisory/subjective. Screen components are cohesive; splitting purely to satisfy a line-count heuristic adds indirection without clear benefit. Deferred.
only-export-components (app/_layout.tsx)1False positive. unstable_settings and the ErrorBoundary re-export are required Expo Router route exports. Removing them breaks routing. Fast Refresh on the root layout is moot.
no-danger (app/+html.tsx)1False positive. Expo Router's standard web static-render escape hatch; compile-time constant CSS, no user input.
